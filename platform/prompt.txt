# Build the Drone Safety Platform Ground Control Center — frontend

You have two briefs in this repo. Read BOTH before writing code:

1. **`design_handoff_ground_control/PRD.md`** — the UI product brief. Sections 4
   (the `DataSource` contract), 6 (screens), 7 (component states), and 8 (safety
   UX) are BINDING.
2. **`prd in folder`** — the backend/drone brief (drone software, live data
   backend, simulator, hardware, the `LiveDataProvider`).

And use the design system as the visual source of truth:

3. **`design_handoff_ground_control/README.md`** — implementation guide: full token
   set, every screen/state, the manual-control contract extension, and safety rules.
4. The parent design system — `readme.md`, `styles.css`, `tokens/*`,
   `components/*`, and `ui_kits/ground-control/*` (the runnable HTML/JSX prototype).

## What to build
The complete **React 18 + TypeScript + Vite + Tailwind + lucide-react** frontend
for the desktop GCS, exactly as the UI PRD specifies. The HTML/JSX in
`ui_kits/ground-control/` is a high-fidelity reference prototype — **recreate it
pixel-faithfully in the real stack**, do not paste it. Map the CSS custom
properties in `tokens/*.css` into Tailwind theme tokens; no scattered hex values.

## The seam — do this exactly
- Put the PRD §4 types + `DataSource` interface in `src/contract/` as the single
  source of truth. No `any` in the contract.
- Port `ui_kits/ground-control/mock.js` into a `MockDataProvider implements
  DataSource` in `src/dataSource/`. Keep its state machine and lifelike behavior.
- Build `LiveDataProvider implements DataSource` against the SAME interface, wired
  to the backend from CODE_PRD.md (MAVLink/telemetry/video/tracking).
- Selection is ONE line: `export const dataSource = new MockDataProvider()` →
  `new LiveDataProvider()`. The whole app consumes data only through a single
  `DataSourceContext`.

## Manual control (contract extension — already in the prototype)
Implement the game-controller piloting shown in `ManualControl.jsx`:
- Commands `engageManual` / `disengageManual`; high-rate stick input via a direct
  `setManualInput({ throttle, yaw, pitch, roll })` (−1…1) that bypasses the ack path.
- Gamepad mapping: `axes[0]`=yaw, `−axes[1]`=throttle, `axes[2]`=roll, `−axes[3]`=pitch;
  deadzone 0.09; B/Circle = release. Keyboard fallback W/S, A/D, ↑/↓, ←/→.
- In `LiveDataProvider`, route this to the appropriate manual/RC-override path on
  the vehicle. Document the message shape so the backend can honor it.

## Must-haves
- All screens/panels/components in PRD §6–§7, every state in §7.
- The three modals the prototype does NOT yet implement (PRD §6.7): **failsafe &
  geofence config**, **PID/gain tuning**, **flight-log browser + replay**. Build
  these from the spec; persist via a `SettingsStore` abstraction (in-memory default).
- Map panel = `react-leaflet` over Google/OSM satellite tiles, offline-tolerant
  (last position + grid if tiles fail).
- Instruments (artificial horizon, compass, gauges) as custom SVG/Canvas, matching
  the prototype's geometry and the glide/snap motion rules.
- Safety UX (§8) enforced: checklist gates Arm; Takeoff / Engage / Take-manual are
  hold-to-confirm; Disarm/Disengage/Release are instant; persistent banner while
  tracking OR manual is active; critical statusText surfaces as a toast. Keyboard:
  Space=disarm, T=engage, D=disengage, R=RTL.
- Electron-ready: all I/O behind `DataSource`; no Node/Electron calls in renderer.
- Pin every dependency version. Self-host Geist + JetBrains Mono woff2 (don't rely
  on Google Fonts for the Electron build).

## Acceptance
`npm install && npm run dev` launches the control center on `MockDataProvider`:
animated telemetry, the synthetic video scene with click-selectable people,
working flight + tracking + manual controls, all panels, all modals, a flowing log
— no backend. Then swapping the one line to `LiveDataProvider` connects it to the
CODE_PRD backend with zero UI changes.

Make sensible, opinionated decisions and document them in the README. Favor
completeness.
